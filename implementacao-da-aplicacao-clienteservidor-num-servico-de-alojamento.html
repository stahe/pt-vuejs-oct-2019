    20. Implementação da aplicação cliente/servidor num serviço de alojamento

    Aqui descrevemos a implementação da aplicação cliente/servidor que desenvolvemos num servidor OVH [https://www.ovh.com/fr/]. A implementação noutros fornecedores de alojamento não deverá ser muito diferente. Pretendemos simplesmente mostrar que a nossa aplicação se adapta bem a esta implementação.

    20.1. Implantação no servidor

    O serviço de alojamento da OVH em questão é um plano de alojamento básico:

    1. um ambiente PHP 7.3;
    2. um SGBD MySQL;
    3. sem servidor [Redis];

    O terceiro ponto exige que modifiquemos a versão 14 do nosso servidor de cálculo de impostos.

    Precisamos de modificar:

    • os ficheiros de configuração [1];
    • os controladores [AdminDataController] e [CalculerImpotController] para ter em conta o facto de não existir um servidor [Redis];

    O ficheiro [config.json] é alterado da seguinte forma:

    20.2. Implantação do cliente [Vue.js]

    Foi decidido implementar o cliente [Vue.js] na URL [http://machine/apps/impot/client-vuejs/]. Isso resultou nas seguintes alterações:

    Na raiz do [VSCode] [workspace], criámos o seguinte ficheiro [vue.config.js]:

    O ficheiro [vue.config.js] é o seguinte:

    
// vue.config.js
module.exports = {
  // l'URL de service du client [vuejs] du serveur de calcul de l'impôt
  publicPath: '/apps/impot/client-vuejs/'
}

    O ficheiro [router.js] [3] também foi modificado:

    Comentários

    • linha 21: a base da URL foi alterada;

    O ficheiro [config.js] foi modificado da seguinte forma:

    
// utilisation de la bibliothèque [axios]
const axios = require('axios');
// timeout des requêtes HTTP
axios.defaults.timeout = 5000;
// la base des URL du serveur de calcul de l'impôt
// le schéma [https] pose des problèmes à Firefox parce que le serveur de calcul
// de l'impôt envoie un certificat autosigné. ok avec Chrome et Edge. Safari pas testé.
// avec Firefox c'est possible en demandant l'URL ci-dessous directement et en disant à Firefox
// que vous acceptez le risque d'un certificat non signé. Ensuite le client [vuejs] fonctionnera.
axios.defaults.baseURL = 'http://.../apps/impot/serveur-php7';
// on va utiliser des cookies
axios.defaults.withCredentials = true;
 
// export de la configuration
export default {
  // objet [axios]
  axios: axios,
  // délai maximal d'inactivité de la session : 5 mn = 300 s = 300000 ms
  duréeSession: 300000
}

    Depois de concluído este passo, a pasta [dist] contendo a versão de produção gerada foi «carregada» para o servidor OVH na pasta [/.../apps/impot] e, em seguida, renomeada para [client-vuejs], de modo a que o código do cliente ficasse na pasta [/.../apps/impot/client-vuejs/], conforme planeado. Em seguida, nesta pasta, carregámos o seguinte ficheiro [.htaccess]:

    
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /apps/impot/client-vuejs/
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /apps/impot/client-vuejs/index.html [L]
</IfModule>

    Isto deve-se ao facto de o servidor web OVH aqui utilizado ser um servidor Apache. Para outros tipos de servidores, consulte a documentação |https://cli.vuejs.org/guide/deployment.html|.

    20.3. Conclusão

    A versão [vuejs-21] não era essencial. Vimos que a versão [vuejs-20] tratava corretamente os URLs introduzidos pelo utilizador. No entanto, a nova versão oferece uma conveniência adicional ao utilizador. Este pode navegar digitando URLs. A aplicação apresenta então a vista que melhor se adequa ao estado atual (a sessão) da aplicação. Além disso, a versão [vuejs-22] traz melhorias à apresentação da aplicação em dispositivos móveis.
